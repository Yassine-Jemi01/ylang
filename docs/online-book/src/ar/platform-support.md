# دعم الأنظمة والمنصات

تختلف درجة دعم YLang بين الأنظمة. وجود تعليمات تثبيت لمنصة ما لا يعني أن كل Backend أو مكتبة اختيارية تعمل عليها بالمستوى نفسه.

## Linux

Linux هو أحد الأنظمة الأساسية لتطوير C Backend، كما يدعم المسار التجريبي لـ NASM على x86-64. يمكن استخدام GCC أو Clang. وتتوفر حزمة YSPM اختيارية لأنظمة Linux x86-64 المتوافقة.

برامج الطرفية العادية تحتاج إلى مترجم C وMake. أما GUI وGame2D فتحتاجان إلى SDL2 و`pkg-config`. يبقى NASM تجريبياً ويدعم مجموعة أضيق من البرامج.

## macOS

يُختبر macOS باستخدام Clang وGNU Make. ثبّت أدوات Apple للمطورين واستخدم Homebrew لتثبيت GNU Make والاعتماديات الاختيارية. استخدم `gmake` بدلاً من Make المدمج في النظام، لأنه BSD Make.

تحتاج برامج GUI وGame2D إلى ملفات تطوير SDL2 و`pkg-config`.

## Windows

المسار الأصلي الأولي يستهدف Windows بنواة 64-bit باستخدام MinGW-w64 من بيئة MSYS2 MINGW64. يختبر CI بناء المترجم وتشغيل برنامج أصلي والاستيراد النسبي والإدخال القياسي وبعض الاعتماديات.

MSVC غير مدعوم في هذا المسار، ولا يعني نجاح اختبارات Smoke وجود توافق كامل مع Windows أو تطابق جميع الميزات مع Linux وmacOS. راجع [دليل إعداد Windows بالإنجليزية](../reference/WINDOWS.md).

## دعم النظام يختلف عن دعم Backend

C Backend هو المسار الافتراضي والأوسع. أما NASM فهو تجريبي ومحدود بمجموعة من البرامج على Linux x86-64 المدعوم. نجاح `check` لا يضمن أن كل Backend يستطيع بناء الملف نفسه.

قبل إعلان دعم منصة، ابنِ البرنامج على Toolchain المنصة، وشغّل الاختبارات، وتحقق من المكتبات والربط، واختبر الملفات والطرفية وحالات الفشل. إذا كان البرنامج يستخدم GUI، اختبره في جلسة رسومية فعلية.

عند الإبلاغ عن مشكلة، أرفق النظام ومعماريته وإصدار المترجم والـ Backend وأمر البناء ورسالة الخطأ كاملة وأصغر ملف يعيد المشكلة.
