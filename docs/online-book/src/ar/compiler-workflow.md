# مسار عمل المترجم

يفصل YLang بين فحص المصدر وبناء البرنامج التنفيذي. الدورة المعتادة هي: اكتب الكود، افحصه، ابنِه، شغّله، ثم اختبر سلوكه.

## افحص المصدر

```sh
./build/ylang check hello.yl
```

الأمر `check` يفحص البنية والأسماء والتهيئة والأنواع، ولا ينشئ الملف التنفيذي النهائي. عند ظهور خطأ، اقرأ الرسالة كاملة وسجّل الملف والسطر والعمود وكود الخطأ. رسائل المترجم تبقى بالإنجليزية.

نجاح `check` لا يضمن نجاح GCC أو Clang، ولا يضمن دعم كل Backend للميزة نفسها.

## ابنِ البرنامج

```sh
./build/ylang build hello.yl -o hello
```

الخيار `-o` يحدد مسار الناتج. المسار الافتراضي يستخدم C Backend: يولّد المترجم كود C ثم يستدعي GCC أو Clang.

لاختيار Clang:

```sh
./build/ylang build hello.yl -o hello --cc clang
```

إذا نجح الفحص وفشل البناء، افحص رسائل مترجم C أو Linker أيضاً؛ فقد تكون المشكلة في مكتبة أصلية أو الربط.

## شغّل الناتج واختبره

```sh
./hello
```

قارن الناتج بالسلوك المتوقع. اختبر المدخلات العادية والقيم الحدّية وحالات الفشل. نجاح البناء لا يثبت صحة منطق البرنامج.

## افحص كود C الناتج

```sh
./build/ylang emit-c hello.yl -o build/hello.c
```

يمكن قراءة كود C الناتج لفهم مسار الترجمة أو التحقيق في مشكلة. لا تتعامل مع شكله كواجهة مستقرة ما لم يضمن الإصدار ذلك صراحةً.

## مسار NASM التجريبي

على Linux x86-64 المدعوم، يمكن توليد Assembly أو بناء برنامج من المجموعة المحدودة التي يدعمها NASM:

```sh
./build/ylang emit-asm examples/your-program.yl -o build/your-program.asm
./build/ylang build-asm examples/your-program.yl -o build/your-program
```

NASM Backend تجريبي ولا يدعم كل ما يقبله C Backend. راجع [خارطة Backend](../reference/BACKEND-ROADMAP.md).

## شغّل الاختبارات

```sh
make test
```

تشمل المجموعة اختبارات المترجم وواجهات الأدوات والتحقق من تمارين YLanglings. الاختبار لا يُعد ناجحاً إذا توقف مبكراً أو تخطى جزءاً مطلوباً.
