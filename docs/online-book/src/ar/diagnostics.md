# قراءة رسائل المترجم

رسائل مترجم YLang وأكواد التشخيص تبقى باللغة الإنجليزية عمداً. يساعد ذلك على إبقاء النصوص متطابقة في الطرفية والمحررات والـ CI، وعلى البحث عن كود الخطأ كما هو في المصدر.

## كيف تقرأ التشخيص؟

1. ابدأ باسم الملف ورقم السطر والعمود.
2. اقرأ كود الخطأ مثل `E1027` كما هو؛ لا تترجمه ولا تغيّره عند البحث.
3. افهم ما الذي توقعه المترجم وما الذي وجده فعلياً.
4. افتح السطر المشار إليه، ثم افحص الأسطر القريبة إذا كان الخطأ ناتجاً عن قوس أو تصريح سابق.
5. بعد الإصلاح، أعد `ylang check FILE.yl` قبل البناء.

## مراحل مختلفة، أخطاء مختلفة

| المرحلة | مثال على السبب |
|---|---|
| Lexer / Parser | رمز غير صالح أو صياغة ناقصة أو أقواس غير متوازنة. |
| Type checking | عملية تجمع أنواعاً غير متوافقة أو قيمة غير مهيأة. |
| Module loading | مسار استيراد غير موجود أو تجاوز حدود المشروع. |
| Native build | خطأ من GCC/Clang أو مكتبة أصلية أو Linker. |
| Runtime | فشل عملية أو قيمة خارج المجال أو مورد غير متاح. |

لا تخلط بين تشخيص YLang ورسالة GCC أو Clang؛ كل واحدة تصدر من مرحلة مختلفة.

## حدود الموارد

يحد المترجم عدد التشخيصات المطبوعة إلى 100 لكل عملية بناء، ويحد مقتطف السطر إلى 160 Byte. تُهرّب البايتات غير القابلة للطباعة وغير ASCII بدلاً من إدراجها مباشرةً في التشخيص.

من أكواد حدود الموارد:

- `E1027` و`E1028` و`E1029` تتعلق بحدود تحميل الوحدات وحجم المصدر.
- `E1018` و`E1019` تتعلق بعمق تحليل العبارات أو توليد الكود.

## رموز خروج CLI

| الرمز | المعنى |
|---:|---|
| `0` | نجاح. |
| `64` | خطأ استخدام CLI أو مسار غير مدعوم. |
| `65` | ملف مصدر يحتوي على NUL. |
| `66` | تعذر قراءة المصدر. |
| `70` | فشل تخصيص أو تجهيز مورد. |
| `73` | تعذر إنشاء أو فتح ملف إخراج أو مجلد مؤقت. |
| `74` | فشل كتابة أو إغلاق ناتج `fix`. |

اعتمد في Scripts على رموز الخروج والملفات الناتجة، لا على صياغة الرسالة التي قد تتغير.

للبحث عن كود محدد، افتح [مرجع Error Codes بالإنجليزية](../reference/error-codes.md).
