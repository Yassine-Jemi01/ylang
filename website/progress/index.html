01 / Current implementation

What's already on the 3.0 branch?

These components have implementation on the development branch. Their scope and validation status are shown honestly.

On the branch Planned work
IRImplemented · Partial

Typed SSA Intermediate Representation

A typed, C-independent IR with values, types, basic blocks, and explicit control-flow terminators, backed by an IR verifier that checks structural invariants.

CFGImplemented · Partial

IR Verifier

Checks value IDs, operand and result types, terminators, block reachability, dominance, and typed control-flow edge arguments. Adversarial coverage is still expanding.

ASTImplemented · Partial

AST-to-IR Lowering

A growing scalar-language subset can be lowered, including conditionals, loops, value merges, direct calls, and some imported-module calls.

CPrototype

IR-to-C Emitter

An early C code generator consumes verified IR. Developer commands and differential fixtures exist; full backend parity and default-path migration are still pending.

OPTValidation pending

Initial IR Optimizations

Constant folding, propagation, CFG cleanup, dead-code elimination, and conservative simplifications are in development, with checks to preserve potentially trapping operations.

OWNEarly implementation

Initial Ownership Checks

Move-state checks and limited call-scoped borrow-conflict checks exist. This is not yet a complete borrow checker or a comprehensive memory-safety guarantee.

02 / Release direction

What's planned for YLang 3.0?

These are roadmap goals, not claims that the features are available today.

01

LLVM Backend

Generate LLVM IR and native executables, with optimization profiles, debug information, target configuration, and platform support.

02

NASM x86-64 Backend

Generate assembly from the shared IR, including register allocation, stack frames, object generation, and System V / Windows x64 ABI support.

03

A Richer Type System

Generics, traits, enums, exhaustive pattern matching, tuples, slices, iterators, closures, and Option / Result.

04

Ownership & Borrowing

Explicit moves, shared and exclusive borrows, lifetime and alias checks, and deterministic destruction across control-flow exits.

05

Desktop Application Development

Stabilize GUI and Game2D APIs, define a dependable event loop, and make window, image, audio, and graphics resource ownership safer.

06

Platforms, Libraries & Tooling

First-class Linux, Windows, and macOS support, a broader standard library, and better LSP, debugging, and project dependency tooling.

Release status: LLVM, NASM, advanced language features, first-class Windows support, and a complete desktop application workflow are still roadmap work. YLang 3.0 will not be considered stable until compatibility, platform, security, and performance gates pass and the project owner approves the release.
